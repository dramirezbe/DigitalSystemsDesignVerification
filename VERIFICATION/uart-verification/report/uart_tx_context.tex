\section{Module Objective}

The file \texttt{src/uart\_tx.v} implements a simple UART transmitter. Its job is to take an input byte (\texttt{tx\_data}) and send it over the serial line \texttt{tx} using the classic format:

\begin{itemize}
    \item 1 start bit with value \texttt{0}
    \item 8 data bits
    \item 1 stop bit with value \texttt{1}
\end{itemize}

While the byte is being transmitted, the output \texttt{tx\_busy} indicates that the transmitter is busy.

\section{Module Interface}

\begin{lstlisting}[language=Verilog]
module uart_tx #(
    parameter CLK_FREQ  = 27_000_000,
    parameter BAUD_RATE = 115200
)(
    input  wire       clk,
    input  wire       rst_n,
    input  wire       tx_en,
    input  wire [7:0] tx_data,
    output reg        tx,
    output reg        tx_busy
);
\end{lstlisting}

\subsection*{Inputs}

\begin{itemize}
    \item \texttt{clk}: main system clock.
    \item \texttt{rst\_n}: active-low reset. When it is \texttt{0}, the module returns to its initial state.
    \item \texttt{tx\_en}: pulse or enable signal that requests the start of a transmission. It is only sampled in \texttt{s\_IDLE}.
    \item \texttt{tx\_data}: byte to be transmitted.
\end{itemize}

\subsection*{Outputs}

\begin{itemize}
    \item \texttt{tx}: serial output line.
    \item \texttt{tx\_busy}: indicates whether the module is sending data.
\end{itemize}

\section{Parameters}

\begin{lstlisting}[language=Verilog]
localparam CLOCKS_PER_BIT = CLK_FREQ / BAUD_RATE;
\end{lstlisting}

This constant defines how many clock cycles each UART bit should last. The important detail is that the calculation uses \textbf{integer division}; therefore, if \texttt{CLK\_FREQ} is not an exact multiple of \texttt{BAUD\_RATE}, the result is truncated.

For example, if:

\[
\texttt{CLK\_FREQ} = 27\,000\,000
\qquad\text{and}\qquad
\texttt{BAUD\_RATE} = 115200
\]

then:

\[
\texttt{CLOCKS\_PER\_BIT} = \left\lfloor \frac{27\,000\,000}{115200} \right\rfloor = 234
\]

That means each bit remains stable for 234 \texttt{clk} cycles. With these values, the actual bit period is:

\[
\frac{234}{27\,000\,000} \approx 8.667~\mu s
\]

which corresponds to an actual baud rate of approximately:

\[
\frac{27\,000\,000}{234} \approx 115384.6~\text{baud}
\]

In other words, the design does not generate exactly \(115200\) baud, but rather a very close approximation obtained through truncation.

\section{State Machine}

\begin{lstlisting}[language=Verilog]
localparam s_IDLE  = 2'b00;
localparam s_START = 2'b01;
localparam s_DATA  = 2'b10;
localparam s_STOP  = 2'b11;
\end{lstlisting}

The module is organized as a finite-state machine with four stages:

\begin{itemize}
    \item \texttt{s\_IDLE}: waits for a new byte to transmit.
    \item \texttt{s\_START}: sends the start bit.
    \item \texttt{s\_DATA}: sends the 8 data bits.
    \item \texttt{s\_STOP}: sends the stop bit.
\end{itemize}

\section{Internal Registers}

\begin{lstlisting}[language=Verilog]
reg [1:0]  state;
reg [15:0] clk_count;
reg [2:0]  bit_index;
reg [7:0]  tx_data_reg;
\end{lstlisting}

Each register has a specific function:

\begin{itemize}
    \item \texttt{state}: stores the current state of the state machine.
    \item \texttt{clk\_count}: counts how many clock cycles have elapsed within the current bit.
    \item \texttt{bit\_index}: indicates which bit of the byte is being transmitted, from 0 to 7.
    \item \texttt{tx\_data\_reg}: stores a local copy of the byte being transmitted.
\end{itemize}

Storing the data in \texttt{tx\_data\_reg} is important because the input \texttt{tx\_data} could change while the transmission is in progress.

It is also worth noting that \texttt{clk\_count} is 16 bits wide. With the default parameters this is more than enough, because \texttt{CLOCKS\_PER\_BIT = 234}; however, if very high clock frequencies or very low baud rates were used, this width should be checked again.

\section{Main Sequential Block}

\begin{lstlisting}[language=Verilog]
always @(posedge clk or negedge rst_n)
\end{lstlisting}

All transmitter behavior takes place inside this sequential block. That means:

\begin{itemize}
    \item the module updates its registers on every positive edge of the clock,
    \item and if \texttt{rst\_n} goes low to \texttt{0}, it resets immediately.
\end{itemize}

\section{Behavior During Reset}

\begin{lstlisting}[language=Verilog]
if (!rst_n) begin
    state       <= s_IDLE;
    clk_count   <= 0;
    bit_index   <= 0;
    tx_data_reg <= 8'h00;
    tx          <= 1'b1;
    tx_busy     <= 1'b0;
end
\end{lstlisting}

When reset occurs:

\begin{itemize}
    \item the state returns to \texttt{s\_IDLE},
    \item the clock counter is cleared,
    \item the bit index returns to zero,
    \item the local data copy is cleared,
    \item the \texttt{tx} line is set to \texttt{1},
    \item and \texttt{tx\_busy} is set to \texttt{0}.
\end{itemize}

Keeping \texttt{tx} at \texttt{1} is correct, because in UART the line stays high when idle.

\section{State \texttt{s\_IDLE}}

\begin{lstlisting}[language=Verilog]
s_IDLE: begin
    tx        <= 1'b1;
    clk_count <= 0;
    bit_index <= 0;
    
    if (tx_en) begin
        tx_data_reg <= tx_data;
        tx_busy     <= 1'b1;
        state       <= s_START;
    end else begin
        tx_busy     <= 1'b0;
        state       <= s_IDLE;
    end
end
\end{lstlisting}

This is the idle state.

\begin{itemize}
    \item The output \texttt{tx} stays at \texttt{1}, because nothing is being transmitted.
    \item \texttt{clk\_count} and \texttt{bit\_index} are reset to prepare for a new transmission.
    \item If \texttt{tx\_en} is asserted, the module captures \texttt{tx\_data}, sets \texttt{tx\_busy = 1}, and moves to \texttt{s\_START}.
    \item If \texttt{tx\_en} is not asserted, the module keeps waiting.
\end{itemize}

In other words, \texttt{s\_IDLE} detects the beginning of a new operation. Because everything happens inside a sequential block, detecting \texttt{tx\_en} does not make \texttt{tx} go low in that same cycle: the start bit appears on the next clock edge, when the FSM is already executing \texttt{s\_START}.

\section{State \texttt{s\_START}}

\begin{lstlisting}[language=Verilog]
s_START: begin
    tx <= 1'b0;
    if (clk_count < CLOCKS_PER_BIT - 1) begin
        clk_count <= clk_count + 1;
        state     <= s_START;
    end else begin
        clk_count <= 0;
        state     <= s_DATA;
    end
end
\end{lstlisting}

This is where the start bit is transmitted.

\begin{itemize}
    \item The output \texttt{tx} is forced to \texttt{0}.
    \item \texttt{clk\_count} increments cycle by cycle.
    \item As long as the full bit duration has not elapsed, the state does not change.
    \item When the count is complete, \texttt{clk\_count} is reset and the FSM moves to \texttt{s\_DATA}.
\end{itemize}

The main idea is that the start bit lasts exactly one bit time measured in \texttt{clk} cycles.

\section{State \texttt{s\_DATA}}

\begin{lstlisting}[language=Verilog]
s_DATA: begin
    tx <= tx_data_reg[bit_index];
    if (clk_count < CLOCKS_PER_BIT - 1) begin
        clk_count <= clk_count + 1;
        state     <= s_DATA;
    end else begin
        clk_count <= 0;
        if (bit_index < 7) begin
            bit_index <= bit_index + 1;
            state     <= s_DATA;
        end else begin
            bit_index <= 0;
            state     <= s_STOP;
        end
    end
end
\end{lstlisting}

This is the most important block, because the 8 bits of the byte are transmitted here.

\subsection*{What Is Sent}

The line:

\begin{lstlisting}[language=Verilog]
tx <= tx_data_reg[bit_index];
\end{lstlisting}

makes the output present the bit selected by \texttt{bit\_index}. Since \texttt{bit\_index} starts at 0, the module sends the least significant bit (\texttt{LSB}) first. That behavior matches the classic UART protocol.

\subsection*{How It Advances}

\begin{itemize}
    \item During one bit time, \texttt{clk\_count} counts the clock cycles.
    \item When that time ends, the module decides whether it should move to the next bit or finish the payload.
    \item If \texttt{bit\_index < 7}, it increments the index and remains in \texttt{s\_DATA}.
    \item If bit 7 has already been transmitted, it resets \texttt{bit\_index} and moves to \texttt{s\_STOP}.
\end{itemize}

\section{State \texttt{s\_STOP}}

\begin{lstlisting}[language=Verilog]
s_STOP: begin
    tx <= 1'b1;
    if (clk_count < CLOCKS_PER_BIT - 1) begin
        clk_count <= clk_count + 1;
        state     <= s_STOP;
    end else begin
        clk_count <= 0;
        state     <= s_IDLE;
    end
end
\end{lstlisting}

In this state, the stop bit is transmitted:

\begin{itemize}
    \item the \texttt{tx} line returns to \texttt{1},
    \item the module waits for one full bit time,
    \item and then it returns to \texttt{s\_IDLE}.
\end{itemize}

When it returns to \texttt{s\_IDLE}, the transmitter is ready to accept another byte. The \texttt{tx} signal remains high both during this stop bit and during idle.

\section{Complete Transmission Sequence}

If we want to transmit, for example, the byte:

\[
\texttt{tx\_data} = 8'b1010\,1100
\]

then the order on the \texttt{tx} line will be:

\begin{enumerate}
    \item idle: \texttt{1}
    \item start bit: \texttt{0}
    \item bit 0
    \item bit 1
    \item bit 2
    \item bit 3
    \item bit 4
    \item bit 5
    \item bit 6
    \item bit 7
    \item stop bit: \texttt{1}
\end{enumerate}

Since UART transmits the least significant bit first, the actual order of the data bits will be:

\[
0,\ 0,\ 1,\ 1,\ 0,\ 1,\ 0,\ 1
\]

\section{Role of \texttt{tx\_busy}}

The \texttt{tx\_busy} signal is asserted when the module detects \texttt{tx\_en} in \texttt{s\_IDLE}. Its purpose is to indicate that the transmitter is busy and should not receive a new request.

In this design, \texttt{tx\_busy} is not reassigned in \texttt{s\_START}, \texttt{s\_DATA}, or \texttt{s\_STOP}, so it keeps the value \texttt{1} throughout the entire transmission. It is only cleared on the next evaluation of \texttt{s\_IDLE} when \texttt{tx\_en = 0}. This makes it a simple control flag for the rest of the system, but it also shows that \texttt{tx\_busy} is not wired directly to the current state; it reflects the most recently registered value.

\section{Functional Summary}

The overall behavior can be summarized as follows:

\begin{enumerate}
    \item the module waits in \texttt{s\_IDLE},
    \item when \texttt{tx\_en} is asserted, it stores the byte,
    \item it sends a start bit in \texttt{s\_START},
    \item it sends the 8 data bits in \texttt{s\_DATA},
    \item it sends a stop bit in \texttt{s\_STOP},
    \item and then it returns to idle.
\end{enumerate}

\section{Key Implementation Notes}

\begin{itemize}
    \item The design uses a single state machine, which makes its flow easy to follow.
    \item UART timing depends directly on \texttt{CLOCKS\_PER\_BIT}, which here is obtained by integer division.
    \item Data is transmitted \texttt{LSB first}, as is standard in UART.
    \item There is no parity bit and no multiple stop bits; this is a basic 8N1 implementation.
    \item \texttt{tx\_en} is only honored in \texttt{s\_IDLE}; any request while \texttt{tx\_busy = 1} is ignored.
    \item The \texttt{clk\_count} counter is fixed at 16 bits, which is enough for the current configuration but not fully generic for every possible parameter combination.
\end{itemize}

\section{Conclusion}

The implementation of \texttt{uart\_tx.v} is a compact and clear UART transmitter. Internally it combines:

\begin{itemize}
    \item a state machine to organize the transmission sequence,
    \item a counter to define the duration of each bit,
    \item an index to step through the 8 bits of the byte,
    \item and an auxiliary register to preserve the data during the entire transmission.
\end{itemize}

From a learning perspective, this module is a good foundation for understanding serial communication, baud-rate timing, and sequential design in Verilog. At the same time, a careful reading of the RTL reveals important practical details: the actual transmission starts one cycle after detecting \texttt{tx\_en}, \texttt{tx\_busy} is a registered signal, and baud-rate accuracy depends on the truncation used in \texttt{CLOCKS\_PER\_BIT}.
